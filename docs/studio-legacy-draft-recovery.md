# Studio legacy draft recovery limitation

The old sessionStorage key was `studio-draft:<uid>:<projectId>`. The writer stored `draft`, `baseline`, `pending`, and `pendingWrites`, but no independent account or project identity. In particular, `A:legacy` / `p1` and `A` / `legacy:p1` both produce `studio-draft:A:legacy:p1`. Authenticating either account, checking current project ownership, or comparing draft contents cannot establish which pair originally wrote that record. A collision may also have overwritten an earlier record before this fix; it cannot be reconstructed from the surviving entry.

For either identifier containing `:`, Studio uses a pair-encoded v2 key and never reads, copies, modifies, or deletes the ambiguous old key. The warning is unconditional for such identifiers, regardless of whether an old entry exists, so it does not disclose another account's storage. Non-colon pairs continue using the original key, which has only one delimiter and is unambiguous. Existing v2 drafts remain available as before.

## Private, manual recovery only

There is no in-app export or account-restricted recovery for the ambiguous record: authentication alone cannot prove its ownership. Keep the original browser tab open; sessionStorage is tab-scoped and closing the tab or clearing site data can destroy the record. Do not send a storage dump to support or expose it to another account. A trusted operator who is authorized to inspect **all** data in that browser tab may, on that same device, use the browser's developer tools under Application/Storage → Session Storage to make a private backup of the exact legacy entry. Do not edit or delete it. The backup itself contains sensitive draft data and needs equivalent access controls.

Only if independent evidence establishes the record's rightful owner and project may that trusted operator privately copy the draft to that owner. The record itself and a signed-in account do not supply that proof. If the tab is shared across mutually untrusted accounts, or independent ownership cannot be established, do not inspect, export, disclose, or import its contents to either account; preserve the tab and record. No automatic recovery is possible for the unproven record without risking cross-account disclosure. Normal browser storage access is not an isolation boundary against someone controlling the browser or developer tools.
